# Bracket Tab-Switch Shortcuts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `⌘⇧[` (previous) / `⌘⇧]` (next) tab-switch shortcuts with wrap-around, keeping the existing `⌥↑` / `⌥↓` shortcuts working.

**Architecture:** Three localized changes. (1) `TabsModel.moveSelection(by:)` flips from clamp to modulo wrap — shared by all four shortcuts. (2) The View-menu commands rebind to the bracket keys and route through a new shared `SidebarActions.selectTab(by:services:)` helper. (3) `⌥↑` / `⌥↓` are preserved as hidden, zero-size shortcut buttons in the window's root view, calling the same helper.

**Tech Stack:** Swift, SwiftUI (`Commands`, `keyboardShortcut`), GRDB (unchanged), XCTest. macOS app built via `make build` / `make test` (xcodebuild, `Yggdrasil` scheme, `YggdrasilTests` target).

## Global Constraints

- macOS SwiftUI app, Apple Silicon only. Xcode project is generated by XcodeGen — never hand-edit `Yggdrasil.xcodeproj`. This plan touches no project structure, so no `make project` needed.
- ~~Key equivalents bind as base key + explicit modifier flags: `keyboardShortcut("[", modifiers: [.command, .shift])`, **not** the character `{`.~~ **Wrong — corrected 2026-07-28 (PR #59).** AppKit matches a key equivalent against the event's `charactersIgnoringModifiers`, which already has Shift applied, so Cmd+Shift+[ arrives as `"{"` and `"["` + `.shift` never fires. Bind the shifted glyphs: `keyboardShortcut("{", modifiers: [.command, .shift])` / `"}"`. The menu items are also named **Previous/Next Session**, not "Tab". Task 2 below still shows the original (broken) code — read this constraint first.
- Direction convention: `⌘⇧[` = previous (left), `⌘⇧]` = next (right).
- No schema, persistence, or `project.yml` changes.
- Match surrounding code style (comment density, naming). `make format-lint` and `make lint` must pass.

- [ ] **Step 3: Implement the wrap in `moveSelection`**

In `Yggdrasil/Features/Sidebar/TabsModel.swift`, replace `moveSelection` (`:179`):

```swift
    func moveSelection(by delta: Int) {
        guard !tabs.isEmpty else { return }
        let count = tabs.count
        let currentIdx = tabs.firstIndex(where: { $0.id == selectedID }) ?? 0
        // True modulo wrap: Swift's `%` keeps the dividend's sign, so add
        // `count` before the final `%` to handle negative deltas (wrap past
        // the top back to the bottom).
        let newIdx = ((currentIdx + delta) % count + count) % count
        if let id = tabs[newIdx].id {
            select(id)
        }
    }
```

Then delete the now-unused private extension at the bottom of the same file (`:279-283`):

```swift
private extension Comparable {
    func clamped(to range: ClosedRange<Self>) -> Self {
        min(max(self, range.lowerBound), range.upperBound)
    }
}
```

- [ ] **Step 1: Add the shared helper to `SidebarActions`**

In `Yggdrasil/Features/Sidebar/SidebarActions.swift`, add this static function inside `enum SidebarActions` (e.g. after `removeTab`, before `unlinkPR`):

```swift
    /// Move sidebar tab selection by `delta` (wrapping at both ends) and mirror
    /// the new selection onto the live-session host. Shared by the View-menu
    /// commands (⌘⇧[ / ⌘⇧]) and the hidden arrow-key buttons (⌥↑ / ⌥↓) so the
    /// move-then-sync stays in one place.
    static func selectTab(by delta: Int, services: AppServices) {
        services.tabs.moveSelection(by: delta)
        if let id = services.tabs.selectedID {
            services.sessions.selectedID = id
        }
    }
```
