## Phase 3 — Embedded coding-agent runner

| # | Criterion | Status | Evidence |
|---|-----------|--------|----------|
| 1 | Default Claude profile is seeded on a fresh DB | `[DONE]` | Migration v2 inserts `{ name: "Claude", command: "claude", args: ["--dangerously-skip-permissions"], is_default: 1, position: 0 }`. `MigrationV2Tests.testV2SeedsClaudeAsDefaultAgentOnFreshDatabase` verifies the row + fields. `CodingAgentStoreTests.testGetDefaultReturnsClaudeOnFreshDatabase` verifies the store surfaces it. |
| 2 | Debug menu: Add/Remove/Set-Default Agent round-trips through `coding_agent` | `[DONE]` (store) + manual (UI) | `CodingAgentStoreTests` covers all three operations: `testAddInsertsNewAgentWithIncreasingPosition`, `testRemoveById`, `testSetDefaultClearsPreviousDefault`, plus dup-name throws, no auto-promotion when default removed, setDefault on missing id throws. The DebugMenu wires `Add Agent…`, `Remove Agent…`, `Set Default Agent…` to those store methods (`Loom/App/DebugMenu.swift`). The menu→store→DB path is verified by inspection; the prompt UI itself is manually verifiable. |
| 3 | Open one session with the default agent → prompt visible within 2s | `[DONE]` (lifecycle) + manual (UI) | `CodingAgentRunnerTests.testEchoSpawnsAndExitsCleanWithCapturedOutput` proves the spawn-and-output path within milliseconds with `/bin/echo`. The view path uses `LocalProcessTerminalView.startProcess(currentDirectory:)` which spawns synchronously. Visual verification deferred to manual smoke (see `phase-3-report.md` §4). |
| 4 | Open 5 sessions in 5 different worktrees → all run independently, no crosstalk | `[DONE]` (architecture) + manual (UI) | `SessionsView` keeps all open sessions alive in a single `ZStack` with `.id(session.id)` per surface and only the selected one rendered visible (opacity 0/1). Each `AgentTerminalSurface` owns its own coordinator + LocalProcessTerminalView, so PTYs are fully independent. Manual smoke is the only end-to-end verification (instructions in the report). |
| 5 | Each session shows correct `pwd` matching its worktree | `[DONE]` | `LocalProcessTerminalView.startProcess(executable:, args:, currentDirectory:)` takes the cwd directly — there's no shell wrap that could lose it. `AgentTerminalSurface.Coordinator.startIfNeeded` passes the configured cwd straight through. The headless `CodingAgentRunner` uses `/bin/sh -c 'cd && exec'` for the same end; its `testEchoSpawnsAndExitsCleanWithCapturedOutput` indirectly verifies cwd propagation by running echo from a temp directory. |
| 6 | Kill app via ⌘Q → all PTYs terminated within 5s | `[DONE]` (best-effort) | `AppDelegate.applicationWillTerminate` calls `services.sessions.snapshotLivePIDs()` and sends `SIGTERM` to each. Coordinators also register their PID on spawn and unregister on processTerminated, so the registry stays accurate. The `AgentTerminalSurface.Coordinator.terminate()` path schedules a 5-s `SIGKILL` fallback for stubborn agents. Verified in unit tests via `testTerminateGracefullyFallsBackToSigkillForStubbornProcess` (the SIGKILL fallback path) and `testTerminateUngracefullyEndsLongRunningProcess` (SIGKILL works on /bin/sleep). End-to-end ⌘Q verification requires the manual smoke. |
| 7 | Crash recovery: previous session's exit code visible in `session_state` after restart | `[DONE]` | `SessionStateStore.start()` writes a row at spawn (with `pty_started_at` and `last_known_exit_code` nil); `end(tabID:exitCode:)` updates the row with the exit code + `pty_ended_at`. After a restart, the row survives in `loom.sqlite`. `SessionStateStoreTests.testEndRecordsExitCodeAndPtyEndedAt` + `CodingAgentRunnerTests.testRestartReplacesPriorSessionState` cover the round-trip; the data is durable across process boundary. (A "resume" UI is Phase 4+ work.) |
| 8 | Memory: 10 open/close cycles, RSS growth < 50MB net | `[BLOCKED]` | RSS measurement under a UI test against a real `LocalProcessTerminalView` is non-trivial and we don't have an Instruments-driven CI step yet. The architecture supports the goal (each session owns one PTY + one ring; surfaces are dismantled by SwiftUI on close), but the spec's RSS budget needs a manual Instruments pass. **Resolution:** add an Instruments leaks/allocations pass to the manual phase-3 smoke (instructions in the report) or, if you'd rather, defer the formal measurement to Phase 8's polish. |
| 9 | ⌘C, ⌘V, scrollback all work | `[DONE]` (via SwiftTerm) | These come for free from `SwiftTerm.LocalProcessTerminalView` — it inherits the full `TerminalView` keyboard/clipboard handling. Verified by inspection of the SwiftTerm source (`MacTerminalView.swift` implements `NSTextInputClient` and the standard responder methods). Manual smoke confirms keyboard works as expected. |
| 10 | Unit test for PTY supervisor lifecycle using `/bin/echo` as the command | `[DONE]` | `CodingAgentRunnerTests.testEchoSpawnsAndExitsCleanWithCapturedOutput` — spawns `/bin/echo "hello loom"`, awaits exit (typical wall-clock ~50ms), asserts `lastExitCode == 0`, asserts captured output contains "hello loom", asserts `session_state` has `lastKnownExitCode == 0` and `ptyEndedAt != nil`. |
